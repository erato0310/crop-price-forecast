# API 키 신청 가이드

`sources.py`가 합성(synthetic) 데이터가 아니라 실데이터를 쓰려면 아래 4개 포털에서 키를 받아
`.env.example`을 복사한 `.env`에 채워야 한다. 전부 무료·비영리 공모전 목적이면 승인에 문제 없다.

키가 하나도 없어도 파이프라인(`build_dataset.py`, `backtest.py`)은 합성 데이터로 정상 동작한다 —
급하지 않으면 신청은 병행하고 먼저 코드/구조를 검증해도 된다.

---

## 1. KAMIS 오픈API (가격) — `KAMIS_CERT_KEY`, `KAMIS_CERT_ID`

- 신청처: https://www.kamis.or.kr → 상단 "오픈API" 메뉴 → 인증키 신청
- 소요시간: **즉시 발급** (이메일 인증 정도만 필요)
- 받는 값: 인증키(cert_key) + 인증ID(cert_id) 두 개
- 이게 이 프로젝트에서 **가장 먼저 받아야 할 키** — 가격 시계열이 없으면 예측 대상 자체가 없음.

## 2. 공공데이터포털 (data.go.kr) — `DATA_GO_KR_KEY`

- 신청처: https://www.data.go.kr → 회원가입 → 로그인
- 인증키는 **계정당 1개**를 여러 API에 공통으로 씀. 단, API마다 "활용신청"을 개별로 해야 함:
  1. **기상청 지상(종관, ASOS) 일자료 조회서비스** — 검색창에 "ASOS 일자료" → 활용신청 → 보통 **즉시 승인**
  2. **농축산물 소득정보(3060748)** — 승인 후 "미리보기/요청URL"에 나오는 `uddi:...` 값을 `INCOME_UDDI`에 복사.
     (연 1회 갱신 데이터라 API 대신 자료집 CSV를 한 번 받아 써도 무방 — `docs/RESOLVE_GUIDE.md` 1번 참고)
  3. **흙토람 토양환경정보 - 작물별 토양적성** — 검색 "토양적성" → 활용신청 → 대체로 즉시~1일
  4. **관세청 수출입무역통계(품목별)** — 검색 "수출입무역통계" → 활용신청. 상추는 신선채소라
     수입이 사실상 없어 **우선순위 낮음** — 상추만 할 거면 건너뛰어도 됨.
- 활용신청 후 승인까지 자동승인이 대부분이지만, 기관에 따라 최대 1~2일 걸릴 수 있음.

## 3. KOSIS 오픈API (재배면적) — `KOSIS_KEY`

- 신청처: https://kosis.kr → 회원가입 → 우측 상단 "OpenAPI" → 활용신청
- 소요시간: **즉시 발급**
- 재배면적은 연 단위라 없어도 월별 가격 예측은 가능하지만, 있으면 "공급 증가/감소 → 가격" 관계를
  피처로 넣을 수 있어 정확도에 도움됨 (선택이지만 권장).

## 4. 한국은행 ECOS 오픈API (환율·소비자심리) — `BOK_ECOS_KEY`

- 신청처: https://ecos.bok.or.kr → 회원가입 → OpenAPI → 인증키 신청
- 소요시간: **즉시 발급**
- "국내외 정세 변동으로 인한 소비 패턴"을 정량 피처로 대체하는 역할 (환율, 소비자심리지수).
  뉴스/정세 자체를 분석하는 건 이번 MVP 범위 밖 — 거시 지표로 근사한다.

---

## 키를 받은 뒤

1. `.env.example`을 `.env`로 복사하고 받은 값을 채운다.
2. `cd src && python check_sources.py` 실행 → 상태표에서 `keys_ready`가 True로,
   실제 로더 점검에서 `✔ 실데이터 N행`으로 바뀌는지 확인한다.
3. KAMIS만 먼저 받았다면 가격 소스만 실데이터로 바뀌고 나머지는 여전히 폴백인 게 정상 —
   순서대로 하나씩 채워가면 됨.
4. 상추 관련 코드값(`kamis_item` 등)이 아직 TODO라 키가 있어도 가격 로더는 빈 결과를 낼 수 있다 —
   `docs/RESOLVE_GUIDE.md`의 "0) 상추 코드" 절차대로 코드값부터 채운다.

## 실제 키로 확인된 문제 (2026-08-04 실측)

발급받은 키로 `check_sources.py`/직접 호출 테스트한 결과:

- **KAMIS**: 키 정상 동작. 단 `periodProductList` 액션이 **최근 1년치만 조회 가능** —
  그보다 오래된 날짜를 요청하면 에러 없이 조용히 최근 1년 데이터로 바뀐다. 10년 히스토리는
  이 API로 못 받는다 — 대안은 `docs/RESOLVE_GUIDE.md`의 "-1)" 절 참고.
- **KOSIS**: 정상 동작 확인 (`statisticsList.do` 응답 성공).
- **한국은행 ECOS**: 정상 동작 확인 (환율 데이터 정상 수신).
- **기상청 ASOS (data.go.kr)**: 처음엔 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 났지만
  활용신청은 이미 자동승인된 상태였음 — **진짜 원인은 이중 URL 인코딩**이었다.
  data.go.kr은 "인코딩(Encoding)"과 "디코딩(Decoding)" 두 버전의 키를 주는데, `requests`
  라이브러리는 `params=` 딕셔너리에 넣은 값을 자체적으로 다시 퍼센트 인코딩한다. 이미 인코딩된
  키(`%2B`, `%2F`, `%3D` 같은 게 보이면 이거)를 넣으면 이중 인코딩되어 인증에 실패한다.
  → **수정 완료**: `sources.py`가 `DATA_GO_KR_KEY`를 읽을 때 `urllib.parse.unquote()`로
  자동 디코딩하도록 고쳐서, `.env`에 인코딩/디코딩 버전 어느 쪽을 넣어도 정상 동작하게 만들었다.
- (참고) `sources.py`의 data.go.kr 엔드포인트를 `http://` → `https://`로 이미 고쳐뒀음
  (예전 코드가 http로 되어 있었는데, 요즘 공공데이터포털은 https만 안정적으로 응답함).
